# Updated Report: Stubs, Placeholders, and Semi-Implemented Features

## Summary

Following the updates to `glyim-lower` and `glyim-codegen-llvm`, several critical issues from the previous audit have been resolved. Notably, **string literals**, **enum/aggregate codegen**, **subslice projections**, and **landingpad/cleanup blocks** are now fully or partially implemented. 

However, new stubs were introduced in the THIR-to-MIR lowering pass, and several older critical issues in the bytecode backend and HIR lowering remain. Below is the revised, comprehensive report reflecting the current state of the codebase.

---

## CRITICAL — Functionality That Will Produce Wrong Output or Crash

### 1. Float-to-Float Casts Use IntToFloat
**File:** `glyim-lower/src/builder/lower_expr.rs` — `lower_expr_to_rvalue()` for `thir::ExprKind::Cast`
```rust
(TyKind::Float(_), TyKind::Float(_)) => CastKind::IntToFloat,
```
Casting between float types (e.g., `f64` to `f32`) is mapped to `CastKind::IntToFloat`. This will cause incorrect codegen as it assumes an integer source.

### 2. Dynamic Dispatch (Trait Objects) is Stubbed
**File:** `glyim-lower/src/builder/lower_expr.rs` — `lower_expr_to_rvalue()` for `thir::ExprKind::DynamicCall`
```rust
// Dynamic dispatch via vtable.
// Placeholder for now; full implementation will be added later.
self.diagnostics.push(GlyimDiagnostic::type_error(
    expr.span,
    "dynamic dispatch via trait objects not yet fully implemented",
));
glyim_mir::Rvalue::Use(glyim_mir::Operand::Constant(mir::MirConst {
    kind: glyim_mir::MirConstKind::Unit, ...
}))
```
Trait object method calls are completely unimplemented and will silently compile to `Unit`.

### 3. Slice Pattern Binding is Stubbed
**File:** `glyim-lower/src/builder/lower_expr.rs` — `bind_pattern()`
```rust
thir::PatternKind::Slice { prefix: _, slice: _, suffix: _ } => {
    // Slice pattern lowering is not yet implemented.
    tracing::debug!("Slice pattern lowering skipped (typeck only)");
}
```
While slice *codegen* was implemented, the MIR builder silently ignores slice patterns (`[a, .., b]`). Variables inside slice patterns won't be bound.

### 4. Signed Shift Right Hardcoded to Logical (Unsigned) Shift
**File:** `glyim-codegen-llvm/src/lower.rs` — `lower_binop()` for `BinOp::Shr`
```rust
self.builder.build_right_shift(l_int, r_int, false, "shr")
```
The `is_signed` parameter is hardcoded to `false`. Signed `>>` on negative integers will produce incorrect results.

### 5. Division/Remainder Always Uses Signed Variants
**File:** `glyim-codegen-llvm/src/lower.rs` — `lower_binop()` for `BinOp::Div` and `BinOp::Rem`
```rust
self.builder.build_int_signed_div(l_int, r_int, "div")
self.builder.build_int_signed_rem(l_int, r_int, "rem")
```
Unsigned integer division/remainder will produce incorrect results for large unsigned values.

### 6. Array Type Lengths Not Evaluated
**File:** `glyim-hir/src/lower/lower_type.rs` — `lower_type_ref()` for `ArrayType`
```rust
SyntaxKind::LitExpr => {
    len = Some(ConstRef::Error);
}
```
Array type lengths from literal expressions are always `ConstRef::Error`. Array types `[T; N]` will not have correct lengths.

### 7. Unknown Binary Operators Default to Addition
**File:** `glyim-hir/src/lower/lower_expr.rs` — `lower_bin_op_token()`
```rust
_ => {
    tracing::warn!("STUB: unknown bin op {:?}", token.text());
    BinOp::Add
}
```
Any unrecognized binary operator silently becomes `+`.

### 8. Type System Panics in Codegen
**File:** `glyim-codegen-llvm/src/types.rs` — `llvm_type_for_ty()`
```rust
TyKind::Projection(_) => panic!("type normalization incomplete")
TyKind::Param(param) => panic!("monomorphization should have resolved this")
TyKind::Bound(debruijn, var) => panic!("binder instantiation failed")
TyKind::Infer(var) => panic!("type inference incomplete")
```
Any incompletely-resolved type reaching codegen will panic.

### 9. Bytecode Backend String Constants Are Wrong
**File:** `glyim-codegen/src/lib.rs` — `emit_operand()` for `MirConstKind::String`
```rust
let idx = self.intern_string("string_payload");  // hardcoded, not the actual string
```
The actual string name is ignored; all string constants become the same interned placeholder.

### 10. Bytecode Backend `generate()` Ignores Output Path
**File:** `glyim-codegen/src/lib.rs`
```rust
fn generate(&self, bodies: &[Arc<Body>], _output: &Path) -> CompResult<()> {
    for body in bodies {
        let _ = self.generate_function(body)?;  // result discarded!
    }
    Ok(())
}
```
The generated bytecode is discarded and nothing is written to disk.

### 11. Bytecode Backend ConstantIndex `from_end` Is Wrong
**File:** `glyim-codegen/src/lib.rs` — `emit_place_address()` for `ConstantIndex`
```rust
let index_val = if *from_end {
    *offset // Fallback: use offset as is (will be wrong for from_end)
} else {
    *offset
};
```

### 12. Bytecode Backend Subslice Not Implemented
**File:** `glyim-codegen/src/lib.rs` — `emit_place_address()` for `Subslice`
```rust
tracing::warn!("Subslice projection in bytecode backend: not fully implemented");
bc.push(OP_LOAD_CONST);
bc.extend_from_slice(&0i64.to_le_bytes());
```
Emits a dummy zero offset instead of correctly subslicing.

## HIGH — Missing Features That Limit Functionality

### 13. `type_needs_drop` Is Overly Simplistic
**File:** `glyim-codegen-llvm/src/lower.rs`
```rust
fn type_needs_drop(&self, ty: Ty) -> bool {
    match self.ty_ctx.ty_kind(ty) {
        glyim_type::TyKind::Adt(_, _) => true,
        glyim_type::TyKind::Closure(_, _) => true,
        _ => false,
    }
}
```
All ADTs and closures are assumed to need dropping. Types like `Copy` structs will get unnecessary drop calls.

### 14. ABI: Enum Tag Type Hardcoded to `Ty::BOOL`
**File:** `glyim-codegen-llvm/src/abi.rs`
```rust
let variants_shape = VariantsShape::Multiple {
    tag: glyim_type::Ty::BOOL,  // should be based on variant count
    ...
};
```
Enum discriminant type is always `bool` instead of being computed from the number of variants.

### 15. Generics Not Lowered in HIR
**File:** `glyim-hir/src/lower/lower_item.rs`
```rust
generic_params: Vec::new(),    // always empty
where_clauses: Vec::new(),     // always empty
is_async: false,               // always false
is_unsafe: false,              // always false
```
Generic parameters, where clauses, async, and unsafe annotations are never lowered from syntax.

### 16. Drop and Dealloc Functions Stored but Never Used
**File:** `glyim-codegen-llvm/src/lower.rs` — `LoweringCtx`
```rust
_drop_fn: inkwell::values::FunctionValue<'ctx>,
_dealloc_fn: inkwell::values::FunctionValue<'ctx>,
```
Both are created and stored but never invoked. Memory deallocation for heap-allocated types is not implemented.

### 17. Debug Info for Enums Is Simplified
**File:** `glyim-codegen-llvm/src/debug.rs` — `debug_type_for_ty()`
```rust
// For enums, emit a union with discriminant and variants.
// For simplicity, emit a struct with tag and byte array for now.
let tag_ty = self.builder.create_basic_type("i32", 32, 0x05, 0).unwrap().as_type();
let data_ty = self.builder.create_basic_type("i8", 8, 0x05, 0).unwrap().as_type();
```
Enum debug types are emitted as `{ i32, i8 }` regardless of actual variant data.

### 18. Debug Info for Local Variables Uses Wrong Type
**File:** `glyim-codegen-llvm/src/debug.rs` — `declare_local()`
```rust
let basic_ty = self.debug_type_for_ty(context, ty_ctx.error_ty(), ty_ctx);
```
All local variables get the error type's debug type instead of their actual type.

### 19. Debug Info Hardcodes Line/Column
**File:** `glyim-codegen-llvm/src/debug.rs` — `declare_local()`
```rust
let divar = self.builder.create_auto_variable(scope, name, file, 1, ...);
let loc = self.builder.create_debug_location(context, 1, 1, scope, None);
```
All debug variable declarations point to line 1, column 1.

### 20. `clear_debug_location` Is an Empty Stub
**File:** `glyim-codegen-llvm/src/lower.rs`
```rust
#[allow(dead_code)]
fn clear_debug_location(&self) {}
```

## MEDIUM — Incomplete or Simplified Implementations

### 21. Borrow Checker Write-Conflict Two-Phase Check Unused
**File:** `glyim-borrowck/src/lib.rs` — `check_stmt_conflicts()`
```rust
let _in_reservation = if let Some(act) = activation {
    loan_is_in_reservation(loan, current_block, current_stmt_idx, act)
} else {
    false
};
// _in_reservation is never used — write conflicts always fire
```
The two-phase reservation status is computed for write conflicts but discarded.

### 22. Liveness Analysis Only Handles `Assign` Statements
**File:** `glyim-borrowck/src/liveness.rs` — `compute_stmt_liveness()`
`StorageLive`, `StorageDead`, and `Nop` statements are silently ignored in per-statement liveness. `StorageDead` should kill the local.

### 23. `places_conflict` Doesn't Handle `ConstantIndex`/`Subslice`
**File:** `glyim-borrowck/src/visitor.rs` — `places_conflict()`
Falls through to a catch-all that conservatively reports a conflict, potentially causing false-positive borrow errors.

### 24. ABI PassMode Catch-All
**File:** `glyim-codegen-llvm/src/abi.rs` — `fn_abi_of()`
```rust
_ => self.llvm_type_for_ty(arg_abi.ty),  // PassMode::Pair and others not handled
```
`PassMode::Pair` (split across two registers) is not implemented.

### 25. Const Eval: Non-Unit Tuples Not Supported
**File:** `glyim-const-eval/src/eval.rs`
```rust
Expr::Tuple(elements) => { ... Err(ConstEvalError::new("non-unit tuple expressions are not supported" ...)) }
```

### 26. Const Eval: Pattern Matching Limited
**File:** `glyim-const-eval/src/eval.rs` — `pattern_matches()`
Only `Wild`, `Literal`, and `Or` patterns are supported. Struct/tuple/slice/range patterns in const match always fail.

### 27. `FallbackLayoutProvider` Returns Hardcoded Values
**File:** `glyim-codegen/src/lib.rs`
Used when `BytecodeBackend` is created without a `TyCtx`. Will produce completely wrong layouts (everything is 8 bytes).

### 28. Raw Pointer Type Not a Proper Syntax Node
**File:** `glyim-frontend/src/parser/ty.rs`
Raw pointer types (`*const T`, `*mut T`) don't create a syntax node wrapper, making them invisible to downstream consumers.

### 29. Database Mono Cache Not Integrated
**File:** `glyim-db/src/lib.rs`
The mono cache can be set and read, but nothing in the pipeline actually checks or populates it during compilation.

### 30. HIR Lowering: Unhandled Type Node Warning
**File:** `glyim-hir/src/lower/lower_type.rs`
```rust
_ => {
    tracing::warn!("STUB: unhandled type node {:?}", node.kind());
    None
}
```

## Architecture-Level Gaps

### A. No Monomorphization Pass
Types `TyKind::Param`, `TyKind::Projection`, `TyKind::Bound`, and `TyKind::Infer` all panic in codegen. There is no pass between type checking and code generation that resolves generic type parameters.

### B. No Trait Resolution in Codegen
VTable generation exists (`glyim-codegen/src/vtable.rs`) but is not wired into either backend. Dynamic calls are stubbed out in MIR lowering.

### C. No Closure Capture Analysis
`AggregateKind::Closure` is lowered as a plain struct with operand types, but closure captures (upvalues) are not analyzed or stored properly. 

### D. No Linker Integration Beyond `cc`
**File:** `glyim-cli/src/linker.rs` — The linker is a shell-out to `cc` with no support for custom link scripts, cross-compilation linkers, or linker flags.

## Acknowledgement of Fixed Issues
The following critical issues from the previous audit have been successfully resolved in the provided updates:
- **String literals** now correctly generate global constants in LLVM codegen.
- **Enum codegen** now properly handles multiple variants, discriminants, and niche encodings via `build_layout_aggregate`.
- **Subslice projections** are now fully implemented in LLVM codegen (`place_ptr`).
- **Landingpad / Exception Handling** is now properly implemented, correctly emitting `landingpad` instructions and `resume` terminators for cleanup blocks.
