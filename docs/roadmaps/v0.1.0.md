# Glyim v0.1.0 — Definitive production-readiness roadmap

The three answers clarify everything:

1. **`docs/issues/0001..0007` are closed** — so the stdlib blocker described there is gone.
2. **`glyip` is the production entry point** — `glyim-cli` is a lower-level tool.
3. **v0.1.0 requires both** — programs that compile *and* run, and an LSP usable in VS Code.

With those, I can write the roadmap as a plan, not a survey. Every item below is anchored to a probe result from the wave-1/wave-2 logs.

---

## v0.1.0 release definition

A user can:

1. `glyip new hello && cd hello`
2. Edit `src/main.g` to use `println`, `Vec`, `Option`, `Result`, `Iterator`, `String`, and `Box`
3. `glyip run` — compiles, links, executes, prints the right output
4. `glyip test` — discovers, compiles, executes their tests, reports per-test results
5. Open the project in VS Code with a Glyim extension — hover, goto-definition, find-references, rename, code-actions, document symbols, workspace symbols, folding, formatting all work

That is the target. Everything below is on the critical path to it or a hygiene item that prevents shipping.

## Tier 0 — Ground truth refresh (1 week)

Five concrete items. Cheap, and they unblock the rest of the plan by making the state of the world legible.

### 0.1 Close the stale issues and pin them with tests

`docs/issues/0001..0007` describe compiler gaps that no longer exist. Close each one with a note ("resolved in commits X..Y, verified by `<test>`"). For every fix that landed, ensure a regression fixture exists in `crates/glyim-test/tests/run-pass/` or `run-pass/modules/` — if there isn't one, add it. This is *the* reason the plan corpus decayed: no test pinned the specific failure, so nobody could tell if the fix had landed.

**Done when:** `docs/issues/INDEX.md` says `closed` for all 7, and each is referenced by a `.g` fixture that fails if the fix is reverted.

### 0.2 Un-`#[ignore]` the two typeck tests

`crates/glyim-typeck/src/tests/p1_probe.rs:52,93` are the only two `#[ignore]`d tests in the entire workspace. Both describe "KNOWN GAP" generic-impl issues. Run them; if they pass, delete the `#[ignore]` and the `KNOWN_GAPS.md` note. If they fail, they're the real last item on the generic-impl path and become Tier 1.

**Done when:** zero `#[ignore]` in the workspace, or the remaining ones have a linked open issue.

### 0.3 Audit what `glyip new` writes and what `glyip run` does with it

The `glyip new` → `glyip run` path is the user's first experience. Concretely: run `glyip new /tmp/hello && cat /tmp/hello/src/main.g && glyip run` on a clean checkout and record the full session. Then compare against the release definition above. The gap is Tier 1.

### 0.5 Refresh the run-pass corpus to assert stdout

Of 38 `run-pass` fixtures, 34 assert only the exit code. Exit-code-only tests miss the class of bug where the compiler returns the right integer but prints the wrong string, or where `println!` formatting is broken in a way unrelated to the return value. Rewrite each fixture to `println` its result and assert `check-stdout`. Where an exit code is the *point* (testing `fn main() -> i32`), keep it, but add a parallel fixture that prints.

**Done when:** every `run-pass` fixture that uses `println!` has `check-stdout`; every fixture that uses `fn main() -> i32` also has a sibling that prints. `println!` is tested end-to-end for both literal and formatted forms.

## Tier 1 — Make the language usable (2–3 weeks)

The wave-2 probe found the single most important user-facing defect: **`println` is not in scope**. This tier is about closing that, plus the two things a user will hit next.

### 1.1 `println` (and the rest of the prelude) reachable by default

**Evidence:** W6 shows `fn main() { println("hello"); }` → `[T0001] unresolved name 'println'`.

The stdlib is real (`vec.g`, `boxed.g`, `option.g`, `result.g`, `iter.g`, `ops.g` all contain full implementations) and the assembled stdlib compiles as a whole (`stdlib_full_probe` passes). It's just not in scope for a user program.

The fix is one of three designs; pick one and commit:

- **Prelude injection in `glyip`.** When compiling a crate, prepend a synthesized `prelude.g` that contains `use core::{Option, Result, Iterator, ...}; use alloc::{Vec, String, Box, Rc}; use std::io::println;`. This mirrors Rust's prelude model and requires no language change.
- **`Glyip.toml` carries a `prelude = "std"` field**, and the build system injects the corresponding source. More explicit, better for no-std style crates.
- **`use std::*;` explicit imports.** The user writes them. Least friendly, most flexible.

Given the user's stated workflow (`glyip new`, then edit), the first option is correct. The prelude should be **one file** in the stdlib crate (`crates/glyim-lang-std/lib/prelude.g`) that both `glyim-cli` and `glyip` inject when no `--no-prelude` flag is passed.

**Done when:** `glyip new /tmp/hello && cd /tmp/hello && sed -i 's/fn main() {}/fn main() { println("hello"); }/' src/main.g && glyip run` prints `hello`.

### 1.2 `Vec::new()` inference

**Evidence:** W6 shows `let mut v = Vec::new(); v.push(1); v.len()` → `mismatched types: usize vs i32`. My test had a secondary bug (returning `usize` from `fn main() -> i32`), but the underlying issue — that `Vec::new()` doesn't infer `T` from the subsequent `push` — is real and will hit every user.

Reproduce with a clean fixture:
```gleam
fn main() {
    let mut v = Vec::new();
    v.push(1);
    v.push(2);
    let n = v.len();
    println("{}", n);
}
```
Expected `2`. If this fails, the fix is in `glyim-typeck`: `Vec::new()` should produce a `Vec<?T>` with a fresh inference variable that unifies against the argument of `push`.

**Done when:** the above fixture runs and prints `2`.

### 1.3 `glyip run` and `glyip build` use the native backend by default

**Evidence:** W6 proves `--emit=exec` produces a working native Mach-O binary on `aarch64-apple-darwin` with exit `42`. The `glyim-cli` path works. But `glyip` is the entry point, and `glyip run` currently shells out to `glyim_pipeline::Pipeline::compile_file` (which writes an object, not an executable) per `crates/glyip/src/commands.rs:428`.

Verify: does `glyip run /tmp/hello` produce a *runnable* binary? If it only produces an object, `glyip run` is broken for the common case and the fix is to route `glyip build`/`glyip run` through `glyim-cli::run_with_args` with `--emit=exec` (or share the linker path).

**Done when:** `glyip run` on a fresh project prints the program's output.

### 1.4 Fix the 10 LSP capability gaps

**Evidence:** W3 shows `handler.rs` advertises 10 capabilities. `navigation.rs:189` implements `workspace_symbols` with tests in `workspace_symbol_tests.rs` and `navigation_tests.rs`, but `workspace_symbol_provider` is missing from `ServerCapabilities`. Also missing from `ServerCapabilities`: `text_document_sync: INCREMENTAL` (currently `FULL`, which forces a full recompile on every keystroke).

Add:
- `workspace_symbol_provider: Some(OneOf::Left(true))` — one line, feature already works.
- `text_document_sync.change: TextDocumentSyncKind::INCREMENTAL` — requires a `did_change` handler that computes a diff. Currently `did_change` isn't handled at all; without it, VS Code sends `didChange` notifications that are ignored.

The second one is the difference between "the LSP recompiles the whole file on every keystroke" and "the LSP handles incremental edits." For a 500-line file, this is the difference between 50 ms and 5 seconds per keystroke.

**Done when:** a Glyim extension in VS Code shows workspace symbol search, and editing a 500-line file keeps keystroke latency under 100 ms.

### 1.5 `--explain <code>` and a frozen code namespace

**Evidence:** W5 shows `ErrorCode { category: ErrorCategory, number: u16 }` and codes print as `[T0001]`. There is no `--explain` in the CLI. The `E0001` string appears once in the codebase.

Migrate to stable, human-readable codes: `E-PARSE-0001`, `E-TYPE-0001`, `E-BORROW-0001`, `E-ICE-0001`. Write `docs/errors/<code>.md` for each. Add `glyip explain <code>` and `glyim-cli --explain <code>`. Add a CI test that every `DiagCode` variant has a docs file — this is the mechanism that keeps the namespace frozen.

**Done when:** `glyip explain E-TYPE-0001` prints the reference, and adding a new diagnostic without a docs file fails CI.

### 1.6 Supply chain hygiene

**Evidence:** W1 says no `deny.toml`, no `audit.toml`, and the lockfile has `reqwest`, `hyper`, `native-tls`, `openssl`, `rustls`, `ring`, `tokio`, `sha2`, `libloading`.

Add:
- `deny.toml` with a license allowlist (MIT, Apache-2.0, BSD-2/3-Clause, ISC, MPL-2.0, Zlib, Unicode-DFS-2016, CC0-1.0).
- `cargo-deny check licenses advisories bans sources` in a CI job.
- `cargo-audit` in a CI job.

Run both locally. Whatever comes back is a Tier-1 fix.

**Done when:** CI fails on a fresh RUSTSEC advisory, and no duplicate-version crates exist for `openssl`, `native-tls`, `rustls`, or `ring`.

### 1.7 Pin the toolchain

**Evidence:** W1 says no `rust-toolchain.toml`. The workspace is `edition = "2024"` + `resolver = "3"`.

Add `rust-toolchain.toml` with `channel = "1.85.0"` (or whatever the current MSRV is) and `components = ["rustfmt", "clippy", "llvm-tools"]`. Add a CI job that runs the suite against that channel.

**Done when:** CI green on the pinned toolchain. A developer on a newer stable sees the same behavior.

## Tier 2 — Production hardening (4–8 weeks)

### 2.1 Make the native backend the default for tests

**Evidence:** W2 shows `run_pass_corpus.rs` uses `PipelineCompiler::new(mock)` unless `GLYIM_TEST_REAL_LLVM=1`. Since `--emit=exec` works on macOS (W6), the interpreter fallback is masking codegen bugs from the local dev loop.

Change the policy: when `LLVM_SYS_220_PREFIX` is set and `llvm-config` is present, `PipelineCompiler` uses the real `LlvmBackend` by default. Add `GLYIM_TEST_BACKEND=interp|llvm|native` to explicitly choose. The interpreter is a *debugging tool*, not the default.

**Done when:** `cargo nextest run -p glyim-test --test run_pass_corpus` runs native on macOS and Linux CI, and interprets only when explicitly asked.

### 2.2 Extend the native run-pass corpus to macOS and Windows CI

**Evidence:** W2 shows `only-target: x86_64-unknown-linux-gnu` on the two M5 fixtures; the current CI has `test-linux-runtime` as the only native-execution job.

Given that the macOS `-target` linker fix landed (`KNOWN_GAPS` §10.4), and that W6 proves `--emit=exec` works on macOS, add `run-pass-native-macos` to the CI matrix. On Windows, add the job but expect failures — the point is to *see* them, not hide them.

**Done when:** three CI jobs (Linux, macOS, Windows) each run the native `run-pass` corpus, and each prints its pass/fail/skip count to the CI summary.

### 2.3 Fuzz targets

**Evidence:** Wave-1 Section K found zero fuzz targets.

Add `fuzz/` with three targets:
- `fuzz_parse`: `parse_to_syntax` on arbitrary bytes. Must never panic; always returns `Ok` or a diagnostic.
- `fuzz_typeck`: `compile_file_to_mir` on a parser-validated AST. Must terminate within a budget, no panics.
- `fuzz_codegen_ir`: `LlvmBackend::generate_ir` on arbitrary `Body`. Output must pass `llvm-as` verification.

Run each for one hour in a CI job (`cargo fuzz run fuzz_parse -- -max_total_time=3600`). Every panic found is a fix.

**Done when:** each target runs clean for one hour with the current corpus.

### 2.4 Extend Miri coverage

**Evidence:** Wave-1 CI shows Miri covers `glyim-type`, `glyim-borrowck`, `glyim-solve`. The five pure-Rust crates not covered are `glyim-mir`, `glyim-opt`, `glyim-layout`, `glyim-db`, `glyim-hir`.

Add each to the Miri job, one at a time (so failures are visible and attributable). Expect `glyim-mir` to surface OOB in the `IndexVec` usage — that's the point.

**Done when:** Miri runs clean on all eight crates.

### 2.5 Convert production panics to ICEs

**Evidence:** Wave-1 Section L: 19 panics in `glyim-codegen-llvm`, 12 in `glyim-hir`, 7 in `glyim-opt`, 3 in `glyim-type`, 2 in `glyim-solve`, plus smaller counts elsewhere.

Classify each:
- **Invariant** (e.g. `PassMode::Ignore => unreachable!()` in `lower.rs:3186` because the ABI classifier never emits it) → keep, add `debug_assert!` and a comment naming the invariant.
- **User-reachable** (e.g. `panic!("expected Array, got {other:?}")` in `ty_ctx_mut.rs:2662` — a caller with the wrong type) → convert to `Result<T, TypeError>` and propagate.
- **Internal consistency** (e.g. `panic!("MIR failed validation before optimization: {:?}", e)` in `opt/src/lib.rs:52`) → convert to `GlyimDiagnostic::internal_error` with the failing body's span.

Add a `--error-format=json` field for `is_ice: true` so editors can distinguish "user error" from "compiler bug."

**Done when:** `cargo nextest run --workspace` passes with `-D clippy::panic` scoped to production code, or every remaining `panic!()` has a `// SAFETY:`-style comment naming the invariant.

### 2.6 `cargo-mutants` on the analysis crates

**Evidence:** `mutants.out/missed.txt` is empty. Only `tools/glyim-pilot/src/main.rs` was ever mutated.

Run on `glyim-solve`, `glyim-type`, `glyim-borrowck`, `glyim-const-eval`, `glyim-layout` — the correctness-critical crates. Two crates at a time, `--timeout 60`, in a nightly CI job. Triage the misses: a surviving mutant on the "should fail" path means the test suite asserts the happy path but not the rejection.

**Done when:** mutation score is measured, tracked over time, and improving.

### 2.7 `missing_docs` → `deny` per public crate

**Evidence:** W1 says `cargo doc` reports 0 missing docs. That means the pass was done — pin it. Add `#![deny(missing_docs)]` to `glyim-syntax`, `glyim-hir`, `glyim-type`, `glyim-db`, `glyim-diag`, `glyim-codegen`, `glyim-span`, `glyim-core`.

Commit a `cargo public-api` baseline for each. Add a CI job that diffs against the baseline and requires an explicit `PR-API-CHANGE:` line in the PR description on change.

**Done when:** a PR that changes a public type in `glyim-hir` cannot merge without acknowledging the change.

### 2.8 `glyip test` dogfoods the stdlib

**Evidence:** W7 shows `glyip test` discovers and executes tests, and `test_cmd_test_executes_tests` proves the workflow. Add a `glyip test` CI job that runs the stdlib's own tests through the toolchain — not through cargo, through `glyip test`.

**Done when:** the stdlib has a `tests/` directory with `.g` fixtures that `glyip test` executes.

## Tier 3 — v0.2 features (post-v0.1)

### 3.1 Language edition policy

Decide now: does `Glyip.toml` carry `edition = "2024"`? What editions exist? Does the parser branch on it? Without this, v0.2 can't change syntax. Write `docs/specs/editions.md`.

### 3.2 Derive/attribute proc macros

`KNOWN_GAPS` §9.2. Function-like proc macros work; derive (`#[derive(Clone)]`) and attribute (`#[my_attr]`) forms remain.

### 3.3 ThinLTO linker integration

`KNOWN_GAPS` §10.2. `llvm-lto2` thin-link is wired; the multi-CGU merge at link time is the remaining step.

### 3.4 Windows SEH fidelity

`KNOWN_GAPS` §6.1. The Itanium-compatible approximation works on `-gnu` Windows. True funclet SEH needs an LLVM toolchain that exposes `LLVMBuildCleanupPad` (currently absent in the pinned `libLLVM.dylib`).

### 3.5 Language reference document

`docs/specs/v0.1.0.md` and `docs/contracts/v0.1.0.md` exist. Freeze them as the *normative* source of truth for every diagnostic, and add a test that every diagnostic message links to a section.

## Critical path summary

If you did nothing else for two weeks, do these in this order:

| # | Item | Why | Time |
|---|---|---|---|
| 1 | **1.1 Prelude injection in `glyip`** | Without this, no user program compiles | 2–3 days |
| 2 | **1.2 `Vec::new()` inference** | Every non-trivial program hits this | 1 day |
| 3 | **1.3 `glyip run` uses native exec** | Otherwise `glyip run` doesn't run | 1 day |
| 4 | **0.4 + 0.5 Corpus stdout assertions** | Turns 50+ tests from "type-checks" into "behaves correctly" | 2 days |
| 5 | **1.4 LSP capabilities + incremental sync** | LSP goes from "hover and completion" to usable | 2 days |
| 6 | **1.6 + 1.7 Supply chain + toolchain** | Free production-grade hygiene | 4 hours |

After those, v0.1.0 is a defensible release for a motivated early adopter. Tier 2 is the work that turns "defensible" into "recommended."
