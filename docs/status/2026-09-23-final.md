# Glyim progress — 2026-09-23 (final session summary)

Committed at HEAD after Scripts 88-101. All fixes have TDD tests.

## Landed and verified

### Compiler features
1. **Module-scoped generic structs** — resolve_qualified_path makes fresh
   inference vars for 2-segment paths without turbofish.
2. **Impl generic-param bounds** registered before method signature
   resolution (both `typeck_crate` pre-pass and `check_fn_items_in_module`).
3. **2-segment projections** (`I::Item`, `Self::Item`) resolved in
   `resolve_path_type`.
4. **Cross-module const types** — pre-registered in the const's own module.
5. **Non-primitive const value evaluation** skipped (type is what callers need).
6. **Macro expander runs in all emit paths** (`emit_mir`, `emit_llvm_ir`,
   `emit_asm`), not just `compile_file_to_mir`.
7. **Raw-pointer intrinsic methods** — hardcoded table for `*mut T`/`*const T`
   in `resolve_method_call` (is_null, add, sub, addr, as_ptr, as_mut_ptr).
8. **Int ↔ raw-pointer casts** legal, including `Infer(Int)` sources.
9. **Tree-walk trait resolution** — `resolve_path_to_trait_def_id` falls back
   to walking every module scope when the root lookup fails.
10. **`resolve_impl_header` uses the tree-walk resolver** for single-segment
    trait paths.

## Remaining blockers for `println("hi")` via `--with-stdlib`

The E2E path currently reports ~25 diagnostics. Categories:

### 1. `no method alloc` / `no method dealloc` on `GLOBAL` (12+ errors)
**Reproducers PASS in isolation** (Scripts 100-101: `pub mod alloc { pub
trait GlobalAlloc { fn alloc } pub struct Global; impl GlobalAlloc for
Global; pub const GLOBAL: Global } pub use alloc::GLOBAL; pub mod boxed {
GLOBAL.alloc(...) }` all compile). But the assembled stdlib fails.

**Hypothesis**: at scale (28 modules concatenated), `GlobalAlloc`'s
TraitDefId diverges between the trait definition and the impl header — a
similar class to the `Error`/`ErrorKind` id-splitting issue noted in old
docs. Instrument `resolve_impl_header` to print the resolved TraitDefId
for `impl GlobalAlloc for Global` in the stdlib, and compare with the
`TraitDefId` the method-lookup path computes for `GLOBAL.alloc(...)`.

### 2. `no method expect` on `Layout::from_size_align(...)` (6+ errors)
`Result<Layout, LayoutError>::expect` isn't resolving. The receiver is a
`Result` value; `expect` is a method on `Result<T, E>`. The generic
methods on `Result` (`unwrap`, `expect`) should dispatch through the
builtin method table. Debug: instrument `resolve_method_call` to dump
the receiver type for the `expect` call.

### 3. `unresolved type I::Item` (2 residuals)
`impl<I: Iterator> Iterator for Filter<I> { type Item = I::Item; }` and
`impl<B, I: Iterator> Iterator for Map<I, B> { type Item = B; }` — the
first is a 2-segment projection (should be handled by Script 62-75's
branch), the second references `I::Item` in `Map`'s `fn(I::Item) -> B`
field but with the params in a different order (`<B, I>` vs `<I, B>`).

### 4. `conflicting implementations of trait #87` (1)
At mem.g's `pub mod mem { //! ... }` header. Probably two impls of `Drop`
or `Clone` overlapping on `[T]` or similar.

### 5. `mismatched types: <Self as Trait6>::Err vs <T as Trait87>::Err` (1)
`str::parse::<T: FromStr>` — `FromStr::Err` associated type projection.
The impl header's trait is different from the trait that declares `Err`.

### 6. `unresolved type U` (1)
`impl<T: Default> Default for Option<T>` — `U` isn't in the signature.
Likely a stale symbol from a `where` clause or a projection.

### 7. `struct literal requires ADT type`, `field access on non-ADT` (4+)
Downstream cascades from #1 and #2.
