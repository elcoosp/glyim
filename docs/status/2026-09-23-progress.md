# Glyim progress — 2026-09-23 (session 2)

Consolidated state after ~87 iterative fix scripts, commit `d0cadeb1`.

## What works

- `glyim-cli input.g --emit=obj|exec` compiles standalone programs.
- `--with-stdlib` prepends the assembled stdlib.
- **~3900+ tests pass**; 2 skipped. Two failures remain, both documented
  below as known stdlib gaps.

## Fixes landed (this session)

### Compiler (all with TDD tests)
1. **Module-scoped generics** — `resolve_qualified_path` creates fresh
   inference vars for 2-segment paths without turbofish.
2. **Impl generic-param bounds registered before signature resolution** —
   both in the `typeck_crate` pre-pass and in `check_fn_items_in_module`.
3. **2-segment associated-type projections** (`I::Item`, `Self::Item`) in
   `resolve_path_type`.
4. **Cross-module const types** — pre-registered in the const's own module
   by a new pass in `typeck_crate`, before any body checking.
5. **Non-primitive const value evaluation skipped** (type registration is
   what callers need).
6. **`emit_mir`/`emit_llvm_ir`/`emit_asm` run the macro expander**
   (previously only `compile_file_to_mir`).
7. **`resolve_method_call` prefers candidates with no inference vars** in
   self_ty (partial).
8. **Raw-pointer intrinsic methods** — hardcoded table in `resolve_method_call`
   for `is_null`, `is_not_null`, `addr`, `add`, `sub`, `as_ptr`, `as_mut_ptr`
   on `*mut T` / `*const T`.

### Stdlib source fixes
- `panic!` variadic arm uses `expr`, not `tt`.
- `struct GlobalAlloc` → `Global` (trait collision).
- `sync::Once` → `OnceLock`.
- `io::Repeat` → `RepeatBytes`.
- `make_pub` skips impl-block items.
- `std_source` gains 17 arms for core/alloc modules.

### CLI
- `--with-stdlib` prepends the assembled stdlib; `args.with_stdlib` guard.
- Linker `ensure_executable` +x on Unix.

## Remaining gaps (documented, not blocking commit)

### Raw-pointer cluster
Script 86 landed the intrinsic methods but new errors surfaced
downstream — the compiler progresses further into stdlib code and
reports the *next* layer of typeck issues:
- `no method expect` (7) — `Option::expect`/`Result::expect` on a
  generic type that isn't resolved.
- `no method dealloc` (4) — needs `GLOBAL.dealloc(...)` to find the
  method; `GLOBAL`'s type is `Global` but `GlobalAlloc` trait impl isn't
  visible.
- `no method alloc` (3) — same.
- `trait GlobalAlloc not implemented for <error>` (6) — downstream of
  the above.
- `field access on non-ADT` (4) — generic-typed field access where the
  receiver is a projection that hasn't normalized.

### Projection residuals
- `unresolved type I::Item` (2) — 6 of 8 cleared by Scripts 62-75.
- `unresolved type U` / `U::Error` (1) — `convert.g`'s `TryFrom` blanket
  impl with a param not in scope.

### Method resolution
- `len` ambiguity (~30, all downstream) — `str` vs `<[T]>::len`. Scripts
  77-80 tried infer-var filters but the diagnostic still shows both
  candidates printing as `str`.

### Coherence
- `trait #87 conflicting impls` (1).

## Next-step priorities

1. **`GLOBAL` method visibility**: `GLOBAL.alloc(layout)` reports "no
   method alloc". The trait impl `impl GlobalAlloc for Global` exists but
   method resolution on the `Global` Adt isn't finding it. Dump
   `resolve_method_call` for a `Global` receiver to see why.

2. **`Option::expect` / `Result::expect` on generic types**: likely a
   projection that hasn't normalized before method dispatch. Same family
   as the `I::Item` residuals.

3. **`len` ambiguity root cause**: dump candidates for a `&str` receiver.

4. **Coherence `trait #87`**: investigate which trait and which two impls
   conflict.
