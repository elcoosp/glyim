Ce guide montre comment piloter le flux de build au quotidien avec `glyip` : builds debug et release, sélection de backend, niveaux d'optimisation, optimisation à l'édition de liens, et exécution du résultat.

## Compiler un projet

Lancez cette commande dans le répertoire qui contient votre `Glyip.toml` :

<Code lang="bash" code={`glyip build`} />

Le build est incrémental : `glyip` empreinte les sources et la configuration de build avec SHA-256 et ne recompile que ce qui a changé.

## Compiler en mode release

<Code lang="bash" code={`glyip build --release`} />

Combinez `--release` avec un niveau d'optimisation explicite et une stratégie LTO quand vous voulez un build ajusté :

<Code lang="bash" code={`glyip build --release --opt-level 2 --lto thin`} />

<Aside type="caution">
Le LTO `fat` effectue une fusion de modules et une étape d'optimisation dans le compilateur. Le LTO `thin` exige le backend LLVM et l'outil `llvm-lto2` de la même distribution LLVM contre laquelle `glyim-codegen-llvm` a été compilé ; demander `thin` avec le backend bytecode est une erreur explicite plutôt qu'un no-op silencieux.
</Aside>

## Choisir un backend

`glyip build --backend` accepte `llvm` (le défaut, produisant des exécutables natifs) ou `bytecode` (le format à opcodes propre à Glyim, utilisé pour les tests et l'exécution embarquée — sa sortie n'est pas directement exécutable) :

<Code lang="bash" code={`glyip build --backend bytecode`} />

`glyip run` compile toujours avec le backend LLVM, parce qu'exécuter nécessite quelque chose que le système d'exploitation peut démarrer.

## Lancer votre programme avec des arguments

Tout ce qui suit `--` est passé à votre programme :

<Code lang="bash" code={`glyip run -- --flag value`} />

`glyip run` compile d'abord, puis exécute le binaire, et sort avec le statut de sortie de l'enfant. Un programme qui sort avec un statut d'échec produit une invocation `glyip run` en échec.

## Compiler en croisé avec un triple cible

Passez un triple cible pour compiler pour une autre architecture :

<Code lang="bash" code={`glyip run --target aarch64-unknown-linux-gnu`} />

Le triple par défaut est le triple hôte (dérivé de `std::env::consts`). Le même drapeau `--target` existe sur `glyim` (voir la [référence CLI](/reference/cli/)).
