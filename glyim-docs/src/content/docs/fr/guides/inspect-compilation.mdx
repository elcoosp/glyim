Ce guide montre comment regarder dans le compilateur pendant qu'il traite un seul fichier source : émettre des représentations intermédiaires, choisir des backends, régler le codegen et ajuster les niveaux de lint.

Chaque commande ci-dessous compile un fichier nommé `input.g`. Ajoutez `--with-stdlib` quand votre fichier utilise des noms tels que `println`, `Vec`, `Option`, `Result`, `String` ou `Box` — le drapeau préfixe la bibliothèque standard assemblée pour que ces noms se résolvent sans déclarations `use` explicites :

<Code lang="bash" code={`glyim input.g --with-stdlib --emit mir`} />

## Émettre des représentations intermédiaires

Le drapeau `--emit` sélectionne l'artefact de sortie :

<Code lang="bash" code={`glyim input.g --emit mir        # MIR après abaissement — utile pour déboguer l'abaissement
glyim input.g --emit llvm-ir    # IR LLVM du backend LLVM
glyim input.g --emit asm        # assembleur cible
glyim input.g --emit obj        # fichier objet natif (défaut)
glyim input.g --emit exec -o hello   # exécutable lançable
glyim input.g --emit cdylib     # bibliothèque dynamique, utilisée pour les crates proc-macro`} />

Écrivez l'artefact vers un chemin spécifique avec `-o` :

<Code lang="bash" code={`glyim input.g --emit llvm-ir -o out.ll`} />

## Comparer les deux backends

Le drapeau `--backend` sélectionne entre `llvm` (défaut) et `bytecode`. Le backend bytecode émet du bytecode compact de machine à pile que la crate `glyim-bytecode-vm` exécute — utile pour les tests et l'exécution embarquée :

<Code lang="bash" code={`glyim input.g --backend bytecode --emit obj`} />

## Régler l'optimisation et les unités de codegen

<Code lang="bash" code={`glyim input.g -O2 --lto thin          # niveau d'optimisation 2, LTO thin
glyim input.g --codegen-units 4       # partitionner en 4 unités de codegen`} />

- `-O/--opt-level` va de 0 (défaut) à 3.
- `--codegen-units` vaut par défaut la parallélisme disponible plafonnée à 16, reflétant la politique `-C codegen-units` de rustc.
- `--lto` accepte `off` (défaut), `fat` ou `thin`. `fat` exige le support multi-CGU, qui n'est pas encore implémenté, et erreur proprement. `thin` exige l'outil `llvm-lto2` de la distribution LLVM contre laquelle le backend a été compilé.

## Compiler en croisé

<Code lang="bash" code={`glyim input.g --target aarch64-unknown-linux-gnu`} />

Surchargez l'éditeur de liens système et passez des drapeaux supplémentaires quand nécessaire :

<Code lang="bash" code={`glyim input.g --linker /path/to/ld --link-flags "-L/opt/lib -lmylib"`} />

## Obtenir des diagnostics lisibles par machine

Les éditeurs et l'outillage consomment les diagnostics en JSON, un objet par diagnostic :

<Code lang="bash" code={`glyim input.g --error-format json`} />

Le format par défaut `human` rend les diagnostics avec `miette`, y compris les extraits de source et les étiquettes.

## Utiliser des macros procédurales

Compilez d'abord les sources de dépendances proc-macro en cdylibs hôte, puis référencez-les avec une liste séparée par virgules :

<Code lang="bash" code={`glyim proc_macro_dep.g --emit cdylib
glyim main.g --proc-macro-deps proc_macro_dep.g`} />

<Aside type="caution">
La compilation hôte en deux étapes pour les macros procédurales est encore en cours de câblage dans le flux `glyim-cli` par défaut. La surface de drapeaux existe et le pont C-ABI (`glyim-proc-macro`, basé sur `dlopen`) est fonctionnel, mais attendez-vous à des aspérités.
</Aside>

## Ajuster les niveaux de lint

Le compilateur livre actuellement deux lints : `unsafe_fn_call` (alias `unsafe`) et `unused_generic_params` (alias `unused_generics`). Réglez leurs niveaux avec des drapeaux répétables :

<Code lang="bash" code={`glyim input.g -D unsafe                     # promouvoir en erreur
glyim input.g -A unsafe_fn_call             # supprimer
glyim input.g -W unused_generic_params      # remettre en warning (le défaut)
glyim -W help                               # lister tous les lints disponibles`} />

`-A` autorise (supprime), `-W` avertit (défaut), et `-D` dénie, ce qui avorte la compilation à la barrière d'erreur du pipeline. Voir la [référence des lints](/reference/lints/) pour les détails.
