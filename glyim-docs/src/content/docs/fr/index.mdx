Glyim implémente un pipeline de compilation complet : lexing, parsing, résolution de noms, HIR, MIR, inférence de types et résolution de traits, vérification d'emprunts, optimisations, et deux backends de génération de code (LLVM et une VM bytecode personnalisée). Le projet est organisé comme un espace de travail Cargo avec plus de 30 crates, conçu pour la clarté, la testabilité et le développement incrémental. Chaque étage est une crate autonome avec une API publique étroite, donc vous pouvez étudier et tester chaque phase en isolation.

## Points forts

- **Langage de type Rust** — génériques, traits avec types associés, correspondance de motifs, closures avec analyse de capture, `async`/`await`, macros déclaratives et procédurales.
- **Vrai système de types** — inférence avec unification, résolution de traits avec HRTB, calcul d'auto-traits, monomorphisation avec polymorphisation.
- **Vérificateur d'emprunts NLL** — inférence de régions façon Polonius, liveness inter-blocs, emprunts en deux phases, analyse de déplacement avec déplacements partiels.
- **Deux backends** — LLVM 23 via `inkwell` avec abaissement ABI réel et LTO, plus un backend bytecode de machine à pile avec sa propre VM.
- **Chaîne d'outils complète** — le pilote de compilateur `glyim`, l'outil de build `glyip` façon Cargo avec résolution de dépendances et lockfiles, un serveur de langage, et un harnais de test à cinq modes.
- **Syntaxe de vue GSX** <Badge text="experimental" variant="caution" /> — éléments de vue typés de première classe avec un étage de compilateur dédié, réactivité pilotée par l'ownership, et un émetteur SSR.

<Aside type="note">
Glyim est un compilateur de niveau recherche en développement actif. Le pipeline est fonctionnel de bout en bout pour un sous-ensemble substantiel du langage, et Glyim n'est pas encore auto-hébergeur : le compilateur est écrit en Rust, tandis que la bibliothèque standard est écrite en Glyim.
</Aside>
