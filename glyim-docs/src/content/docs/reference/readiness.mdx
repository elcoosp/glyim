The readiness ledger is **computed, never typed**: `glyim-ledger compute` derives every level from machine-checked evidence (passing fixtures, differential runs, fuzzing campaigns) over the registry in `ledger/features/**`. This page renders the committed `STATUS.json` (`glyim.status/1`) at build time, so it can never disagree with the repository's generated [STATUS.md](https://github.com/elcoosp/glyim/blob/main/STATUS.md).

## Feature levels

Every registry entry with its target level, computed level, and the open gaps that cap it.

| Feature | Tier | Target | Computed | Capped by |
|---|---|---|---|---|
{status.entries.map((entry) => `| \`${entry.id}\` | ${entry.tier} | ${entry.target_level} | ${entry.computed_level} | ${entry.capped_by.length > 0 ? entry.capped_by.join(', ') : '-'} |`).join('\n')}

<Aside type="caution">
  Features capped by a `GAP-NNNN` identifier cannot rise above the cap until the gap closes — a silent-miscompile gap (class `b`) always pulls a feature out of "native-verified". The full per-gap audit with witnesses lives in [KNOWN_GAPS.md](https://github.com/elcoosp/glyim/blob/main/KNOWN_GAPS.md).
</Aside>
